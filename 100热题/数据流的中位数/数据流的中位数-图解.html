LeetCode 295 困难数据流的中位数 — 双堆图解

中位数 = 有序序列的中间值；偶数个元素时取两个中间值的平均。

一、题目回顾

设计一个支持两种操作的数据结构：

  • addNum(num)：从数据流中添加一个整数
  • findMedian()：返回目前所有元素的中位数（误差 10-5 内即可）

难点：数据是动态流入的 —— 我们不能等全部数据到齐再排序，每次 addNum 之后随时可能被询问中位数。

二、思路演进：从暴力到双堆

方案addNumfindMedian说明
① 每次全量排序 O(n log n) O(1) 加一个数就排一次序，大量重复比较
② 有序数组 + 二分插入 O(n) O(1) 二分找位置快，但插入要搬移后面所有元素
③ 双堆（对顶堆） O(log n) O(1) 只维护"局部的最大/最小"，不维护全局有序
核心洞察：求中位数根本不需要"整个数组有序"，只需要知道——
比中位数小的那一半里的最大值，以及比中位数大的那一半里的最小值。 恰好，"快速取最大值"是大顶堆的看家本领，"快速取最小值"是小顶堆的看家本领！

三、双堆（对顶堆）模型

分工

  • small（大顶堆）：存放较小的一半数，堆顶是这一半的最大值
  • large（小顶堆）：存放较大的一半数，堆顶是这一半的最小值

不变式（维持的性质）

  • small 中所有元素 ≤ large 中所有元素（堆顶之间相邻，即"对顶"）
  • 元素个数：len(small) == len(large)，或 len(small) == len(large) + 1（small 最多多一个）

求中位数 O(1)

  • 总数为奇数 → 中位数 = small 堆顶
  • 总数为偶数 → 中位数 = (small堆顶 + large堆顶) / 2

插入 num 的统一技巧（先放后调）

  • 先把 num push 进 small（大顶堆），弹出它的堆顶 max；
  • 把这个 max push 进 large；
  • 若此时 len(large) > len(small)，再把 large 的堆顶（最小值）弹回 small。

这样做不需要分类讨论 num 和两个堆顶的大小关系——三步"倒手"天然保证了 small 的所有元素 ≤ large 的所有元素，且个数只会在 small/large 之间偏多一个，两个不变式同时成立。

small — 大顶堆（较小的一半）
堆顶 = 下半部分最大值（Python 中用负号模拟）
large — 小顶堆（较大的一半）
堆顶 = 上半部分最小值

四、Python 实现（heapq 模板）

# Python 的 heapq 只有小顶堆，大顶堆用「取负」模拟：存 -x，弹出时再取负还原
import heapq

class MedianFinder:
    def __init__(self):
        self.small = []  # 大顶堆（存负数）：较小的一半，堆顶是 -max
        self.large = []  # 小顶堆：较大的一半，堆顶是 min

    def addNum(self, num: int) -> None:
        # ① 先放进 small（大顶堆），把它的最大值挤出来给 large
        heapq.heappush(self.small, -num)
        # ② 保证 small 的所有元素 ≤ large 的所有元素
        heapq.heappush(self.large, -heapq.heappop(self.small))
        # ③ 个数平衡：small 最多比 large 多 1
        if len(self.large) > len(self.small):
            heapq.heappush(self.small, -heapq.heappop(self.large))

    def findMedian(self) -> float:
        if len(self.small) > len(self.large):   # 总数为奇数
            return -self.small[0]
        return (-self.small[0] + self.large[0]) / 2  # 偶数取平均

五、逐行追踪示例

数据流依次为 1, 2, 3：

addNumsmall（大顶堆，存负数）large（小顶堆）findMedian
1[-1][]1.0（奇数个，取 small 堆顶）
2[-1][2]1.5（(1+2)/2，取两堆顶平均）
3[-2, -1][3]2.0（奇数个，取 small 堆顶 2）

注意第 3 步（addNum 3）的三步倒手：① 3 先压进 small；② small 挤出最大值 3 交给 large（此时 large = {2, 3} 共 2 个、small = {1} 共 1 个）；③ large 偏多，弹回最小值 2 给 small。最终 small = {1, 2}、large = {3}，总数为奇数，中位数 = small 堆顶 2，全程无需讨论 3 与堆顶的大小关系。

六、复杂度分析

addNum
O(log n)

至多 3 次 heappush / heappop，每次堆操作代价为堆高 log n。

findMedian
O(1)

直接读两个堆顶 small[0] / large[0]，不做任何调整。

空间
O(n)

两个堆共存下所有 n 个元素，各占约一半。

七、常见疑问与拓展

  • Q：为什么"先放后调"不用讨论 num 的大小？
    因为任何数先进 small 后，被挤出的都是"较小一半中的最大值"，把它交给 large 一定满足 ≤ large 全体；数量失衡时再从 large 弹回最小值给 small，两个不变式在每一步都被机械地维护住了。
  • Q：能不能让两个堆"严格各一半"？
    可以，但奇数个元素时中位数落在哪一半需要额外讨论；约定"small 最多多一个"后，奇数情形的中位数永远在 small 堆顶，实现最简洁。
  • Q：Python 怎么建大顶堆？
    标准库里没有大顶堆——heapq 只提供小顶堆，也没有 reverse / key 参数（这点和 Java 的 PriorityQueue 相反）。约定俗成的做法就是本文代码中的「存相反数」法：把数取负丢进小顶堆，取出时再取负还原。嫌负号易错的话，可以把反转逻辑封装进一个 MaxHeap 类（暴露 push / pop / peek），或用包装对象重写 __lt__ 改变比较规则——但负号法最简洁，面试中也是默认写法，至少要看得懂。
  • Q：还有别的做法吗？
    collections.Counter + 桶 / 平衡二叉搜索树（SortedList）、有序容器 + 双指针等也可行，但面试标准答案就是双堆，且它天然适合数据流场景（流式、无需回看历史数据）。
  • 相关题目：剑指 Offer 41、LC 480 滑动窗口中位数、LC 703 数据流中的第 K 大元素（单堆即可）。

双堆模板：分流（small → large）+ 平衡（large → small），把大小比较交给堆自动完成。
