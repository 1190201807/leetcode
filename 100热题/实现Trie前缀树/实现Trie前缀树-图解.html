LeetCode 208 中等实现 Trie (前缀树) — 图解

前缀树（Trie，读作 "try"）：高效存储和检索字符串键集的树形结构，自动补全、拼写检查的底层模型。

一、题目回顾

实现 Trie 类的三个方法：

  • insert(word)：插入字符串 word
  • search(word)：word 是否之前被完整插入过（"app" 插入过 ≠ "apple" 能 search 成功）
  • startsWith(prefix)：是否有插入过的字符串以 prefix 开头（"apple" 插入过 ⇒ startsWith("app") 为 true）

search 与 startsWith 的唯一区别：走到 prefix 的最后一个节点后，search 还要求「有单词恰好在这里结束」，startsWith 则不要求。

二、为什么不用哈希表？

操作哈希表 setTrie
search(word) O(1) O(L) 哈希表略快，但 Trie 支持更多
startsWith(prefix) O(n·L)：只能遍历全部字符串逐个比对 O(L)：沿树走 prefix 长度步即可 这是本题选 Trie 的根本原因
空间（大量共享前缀，如 app / apple / apply） 每个字符串完整存储 公共前缀只存一份，还能做前缀统计
核心洞察：把每个字符串拆成一条字符路径，从根出发一个字符走一步；公共前缀自然汇合成公共路径。 于是「有没有这个前缀」变成「这条路径存不存在」，查询成本只与 prefix 的长度有关，与存了多少个单词无关。

三、节点设计：一个字典 + 一个布尔

Trie 的每个节点只需要两个成员：

  • children：字典 {字符 → 子节点}，表示"从这个节点出发，可以沿哪些字符继续往下走"（用字典而不是 26 长度数组，省空间且不限字符集）
  • is_end：布尔值，标记"是否有单词恰好在此节点结束"——它就是 search 和 startsWith 分道扬镳的地方

四、三个操作怎么走

insert(word) —— 逐字符铺设路径

  • 从根出发，对 word 的每个字符：若下一跳不存在就新建节点，然后移过去
  • 走完所有字符后，把当前节点的 is_end = True

search(word) —— 走路径 + 验收

  • 从根出发逐字符下走；任一步走不通 → False
  • 走通了，还要看终点节点 is_end 是否为 True（路径存在 ≠ 有单词在这里结束）

startsWith(prefix) —— 只走路径，不验收

  • 和 search 前半段完全一样：逐字符下走，走不通 → False
  • 走通了直接返回 True，不看 is_end

观察 search / startsWith 的共同点后可以发现：三者共享同一个「沿字符串下走」的辅助函数，返回走到的节点（或 None），再各自补充验收逻辑。

五、Python 实现

class Trie:
    def __init__(self):
        self.children = {}   # 字符 → 子 Trie 节点
        self.is_end = False  # 是否有单词在此节点结束

    def insert(self, word: str) -> None:
        cur = self                      # 从根出发
        for ch in word:
            if ch not in cur.children:  # 路径断了就现铺
                cur.children[ch] = Trie()
            cur = cur.children[ch]
        cur.is_end = True               # 单词在这里结束

    def _find(self, s: str) -> "Trie | None":
        # 三个方法共用的下走函数：能走完返回终点节点，否则 None
        cur = self
        for ch in s:
            if ch not in cur.children:
                return None
            cur = cur.children[ch]
        return cur

    def search(self, word: str) -> bool:
        node = self._find(word)
        return node is not None and node.is_end   # 走得到 + 是词尾

    def startsWith(self, prefix: str) -> bool:
        return self._find(prefix) is not None      # 只要求走得到

六、逐操作追踪示例

示例输入：insert("apple") → search("apple") → search("app") → startsWith("app") → insert("app") → search("app")

操作树的反应结果
insert("apple")新铺 a-p-p-l-e 五个节点，e 标记 is_end—
search("apple")沿 a→p→p→l→e 走通，e 的 is_end 为真true
search("app")沿 a→p→p 走通，但该节点 is_end 为假（只是路过）false
startsWith("app")沿 a→p→p 走通即返回，不检查 is_endtrue
insert("app")a→p→p 已存在（前缀复用！），只把第二个 p 的 is_end 改为真—
search("app")走通且此时 is_end 已为真true

七、复杂度分析

insert
O(L)

L 为单词长度；逐字符走一步建一步，与树中已有多少单词无关。

search / startsWith
O(L)

同样只与查询串长度有关——这正是相对哈希表遍历 O(n·L) 的优势所在。

空间
O(总字符数)

最坏每个字符一个节点；公共前缀共享节点，实际往往远小于所有字符串长度之和。

八、常见疑问与拓展

  • Q：children 用字典还是长度 26 的数组？
    字典按需创建、不限字符集，Python 里写起来最顺手；数组（[None]*26）索引快、缓存友好，但空间固定 26 倍且只适用小写字母。面试两者都可以，先说清取舍更加分。
  • Q：为什么 search("app") 是 false，明明树里有这条路径？
    因为「路径存在」只说明 app 是某个单词的前缀；是否真的插入过 app 这个完整单词，由终点节点的 is_end 说了算。is_end 就是 Trie 里"句号"的存在。
  • Q：想统计"有多少单词以某前缀开头 / 以某节点结尾"怎么办？
    把 is_end 升级成 pass_count（经过次数）和 end_count（结束次数）两个计数器，insert 时沿途 +1、终点 +1，即可 O(L) 完成统计（如 LC 1804）。
