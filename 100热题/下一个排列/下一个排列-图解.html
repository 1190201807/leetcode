LeetCode 31 中等下一个排列 — 图解

把数组重排成字典序紧接着它的下一个更大的排列；若已是最最大（整体降序），则重排为最小排列（整体升序）。要求原地修改、常数空间。

一、题目回顾

  • [1,2,3] → [1,3,2]：先让最后一位变大，代价最小
  • [2,3,1] → [3,1,2]：末尾 1 无法变大，动倒数第二位；2 变 3 后，把后面排成最小
  • [3,2,1] → [1,2,3]：整体降序 = 已是最大排列，回到最小

规律已经浮现：下一个排列 = 在尽量靠右的位置做一次"变大"，然后把变动位置之后的部分排成最小。

二、核心洞察

洞察 1（降序后缀已是最大）：从右往左看，如果某段后缀是严格降序（如 7,6,5,3,1），那么这段后缀无论怎么内部重排都不可能更大——它是自己能达到的最大排列。想变大，只能动降序后缀左边第一个数（拐点）。
洞察 2（换"大于它的最小者"）：拐点要变大，应换成后缀中比它大的数里最小的那个——只涨一点点，涨多了就越级到"下下个排列"了。
洞察 3（反转即最小）：交换后，后缀依然是降序的，降序的反面就是升序——直接原地反转后缀，就得到后缀的最小排列，无需排序。

三、算法三步走

第 ① 步：从右往左找拐点 i

找第一个满足 nums[i] < nums[i+1] 的位置。此时 [i+1, end] 是降序后缀（最大排列），nums[i] 是唯一能"带增量"的位置。若整趟都找不到（整体降序），说明已是最大排列 → 反转整个数组，结束。

第 ② 步：从右往左找第一个 nums[j] > nums[i]，交换

因为后缀降序，从右往左第一个大于 nums[i] 的数就是"大于它的最小者"（比它小的都排在更右边，从右扫到第一个大的，再往左只会更大）。交换后前半部分刚好完成"最小幅度变大"。

第 ③ 步：反转后缀 [i+1, end]

交换不打乱降序性质（换进来的仍是该位置的合适值），反转降序后缀 = 得到升序 = 最小排列。双指针原地反转，O(n) 时间 O(1) 空间。

四、Python 实现（一次遍历 + 双指针反转）

class Solution:
    def nextPermutation(self, nums: list[int]) -> None:
        """原地修改"""
        # ① 从右往左找拐点：第一个 nums[i] < nums[i+1]
        i = len(nums) - 2
        while i >= 0 and nums[i] >= nums[i + 1]:
            i -= 1                    # 停下时：i 是拐点；i < 0 表示整体降序

        if i >= 0:
            # ② 从右往左找第一个 > nums[i] 的数，交换
            j = len(nums) - 1
            while nums[j] <= nums[i]:
                j -= 1
            nums[i], nums[j] = nums[j], nums[i]

        # ③ 反转降序后缀 [i+1, end]；无拐点时 i=-1，即反转整个数组
        l, r = i + 1, len(nums) - 1
        while l < r:
            nums[l], nums[r] = nums[r], nums[l]
            l += 1
            r -= 1

五、逐例追踪

输入① 拐点 i② 交换的 j③ 反转后
[1,2,3]i=1（2 < 3）j=2，换后 [1,3,2]后缀只有 1 位，不变 → [1,3,2]
[2,3,1]i=0（2 < 3）j=2（1≤2 跳过，3>2），换后 [3,2,1]…反转 [1..2] → [3,1,2]
[3,2,1]无（整体降序）不交换整体反转 → [1,2,3]
[1,5,8,4,7,6,5,3,1]i=3（4 < 7）j=6（5 是 >4 的最小者），换后 …8,5,7,6,4,3,1反转 [4..8] → [1,5,8,5,1,3,4,6,7]

注意 [2,3,1]：拐点是 i=0 而不是 i=1，因为 3,1 降序、2<3；这正是"先让尽量靠右的位置变大"的含义——后缀最大就往前找。

六、复杂度分析

时间
O(n)

找拐点 + 找交换位各最多扫一遍，反转最多扫一遍，三次线性扫描。

空间
O(1)

只用了 i、j、l、r 几个下标变量，完全原地修改。

与全排列生成的关系
1 次调用

反复调用本算法（每 O(n) 一次）即可按字典序遍历全排列，无需生成所有排列再排序（O(n·n!)）。

七、常见疑问与拓展

  • Q：为什么第 ② 步"从右往左第一个大于 nums[i]"就是大于它的最小者？
    后缀是降序的：从右往左数值递增。扫描途中经过的数都 ≤ nums[i]，遇到的第一个 > nums[i] 的数，比它再往左的任何候选数都小——正好是"大于它的最小者"。有重复元素时取最右边那个相等的即可（代码用 <= 跳过相等值自动做到）。
  • Q：交换后后缀还是降序吗？
    是。换出去的是 j 位置的数（原 nums[j] > nums[i]），换进来的是 nums[i]（比后缀中 j 左边所有数都小、比 j 右边所有数都大），j 位置的降序关系在交换前后都成立。
  • Q：为什么"下一个排列"不是把某个更靠左的数变大？
    更靠左变大必然伴随更大规模的重量级重排，字典序增幅更大；拐点右边既然无法内部变大，拐点就是增幅最小的变动点——这是字典序"贪心到最右"的本质。
  • 相关题目：LC 46/47 全排列（回溯）、LC 60 排列序列（直接算第 k 个，不需要逐步生成）、LC 556 下一个更大元素 III（同一算法作用在整数的十进制位上）、LC 1053 交换一次的先前排列（对称的"上一个排列"）。

口诀：右找拐点 → 右找换位 → 反转后缀；找不到拐点就整体反转。
