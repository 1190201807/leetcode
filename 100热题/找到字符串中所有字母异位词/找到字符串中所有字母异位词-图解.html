LC 438找到字符串中所有字母异位词 — 按你的思路图解

题目：给定 s 和 p，找出 s 中所有 p 的异位词子串，返回它们的起始索引。
示例：s = "cbaebabacd", p = "abc" → [0, 6]

一、你的代码在做什么（三条规则）

mapP = Counter(p) # 需求：p 中每个字符要几个 for index, ch in enumerate(s): if ch not in mapP: # 规则①：脏字符 → 窗口作废，l = index+1 windows.clear(); l = index + 1; continue windows[ch] += 1 # 规则②：入窗；若超额 → 收缩到不超额 while windows[ch] > mapP[ch]: windows[s[l]] -= 1; l += 1 if (index - l + 1) == len(p): # 规则③：长度恰好 == len(p) → 异位词！ res.append(l)
💡 为什么"无超额 + 长度恰好"就等于异位词？你的算法始终维护一个不变量：窗口内每个字符的数量 ≤ mapP 的需求（入窗后一旦超额立刻收缩）。于是当窗口长度 == len(p) 时：窗口总字符数 == len(p) == mapP 各需求之和，而逐个字符又有 window[c] ≤ need[c] —— 总量相等 + 每项不超 ⇒ 每项恰好相等。这就是不用 formed/required 计数器也能判定的原因，妙！

三、对照动画看三个关键时刻

  • 🔴 脏字符（规则①）：动画里 'e' 会以红色晃动出现，整个窗口瞬间熄灭、L 直接跳到它右边——windows.clear() + l = index+1。这是你这份代码很有特色的一步：脏字符直接"封印"了窗口左边界，之后不可能再有跨越它的异位词。
  • 🔵 超额收缩（规则②）：左面板某个字符的进度条冲过头变红、标记"超!"时，L 立刻右移把它压回去——while windows[ch] > mapP[ch]。收缩后所有条变回蓝/绿。
  • 🟡 长度命中（规则③）：底部长度指示 窗口长度 == len(p) 的一瞬间，窗口整体闪黄，res 盒子里蹦出起始索引。

注意一个细节：命中判定用的是 index - l + 1 == len(p) 而不是"长度 ≥ len(p)"——因为超额收缩保证了窗口长度永远不会超过 len(p)，所以"恰好等于"就是唯一可能的命中时机。

四、和你之前 LC 76 模板的对比

LC 76 formed 模板你这份代码（LC 438）
覆盖判定formed == required（计数器）不变量：逐字符 ≤ 需求（超额即收缩）
命中时机覆盖后收缩，途中记录最短长度恰好 == len(p) 才记录
脏字符处理无需特判（窗口照常进出）直接清空、L 跳到脏字符右侧
适用场景窗口长度不定（求最短/最长）窗口长度固定（= len(p)）

两套都是 O(m + n) 标准解。固定长度找异位词时，"不变量 + 长度判定"这版少了 formed 的加减维护，思路更直接；LC 567 字符串的排列（判断是否存在异位词）也可以用同样写法。

五、复杂度

时间 O(m + n)

R 扫一遍 s；L 只前进不后退，每个字符最多进出窗口各一次。

空间 O(C)

C 为字符集大小，两个计数表（ASCII 下可视为 O(1)）。
