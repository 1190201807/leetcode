LC 76最小覆盖子串 — 滑动窗口 图解

题目：给定 s 和 t，返回 s 中覆盖 t 全部字符（含重复）的最短窗口子串。
示例：s = "ADOBECODEBANC", t = "ABC" → "BANC"

一、为什么这题可以放心用滑动窗口？

还记得「和为 K 的子数组」为什么不能用滑动窗口吗？——因为负数会破坏单调性。而本题的"覆盖"性质是单调的：

  • R 右移（扩张）：窗口变大只会"更容易覆盖"，覆盖状态不会从 ✓ 退回 ✗；
  • L 右移（收缩）：窗口变小只会"更难覆盖"。

于是有了关键套路：R 负责找可行，L 负责压最短——R 每走一步，只要当前窗口覆盖了 t，就让 L 一路收缩到"刚好不覆盖"为止，收缩途中每一格都是候选答案。每个字符最多进出窗口各一次，总体 O(m+n)。

💡 如何 O(1) 判断"窗口是否覆盖 t"？不开口比较逐个字符：用 need 记录 t 的字符需求，window 记录窗口内计数，再加一个整数 formed（已凑齐的种类数）。某字符数量恰好达到需求时 formed+1，跌破需求时 formed−1，"覆盖" ⟺ formed == required，一次整数比较搞定。

三、算法骨架（就四行主逻辑）

for r in range(m):
    加入 s[r]，若某字符恰好凑齐 → formed += 1
    while formed == required: # 覆盖了！
        先记录答案（当前窗口更短才记录）
        移出 s[l]，若某字符跌破需求 → formed -= 1；l += 1
三个最容易写错的点：
① t 有重复字符：need 存的是数量不是有无（t="aa" 要求窗口里有两个 'a'，这正是示例 3 返回 "" 的原因）；
② formed 只在"恰好达到"和"刚好跌破"时变动：'A' 窗口里有 3 个也只算凑齐 1 次，多出来的不重复计数；
③ 先记录答案、再收缩：while 循环内第一个动作必须是记录当前窗口，否则会漏掉最短的那一个。

四、复杂度

时间 O(m + n)

L 和 R 都只单向前进，每个字符最多进出窗口各一次；每步的覆盖判断是 O(1)（formed == required）。

空间 O(C)

C 为字符集大小，两个计数表最多存 C 种字符（ASCII 下是 O(128) = O(1)）。
