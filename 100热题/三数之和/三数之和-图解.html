LC 15三数之和（3Sum）图解

题目：给定整数数组 nums，找出所有满足 i ≠ j ≠ k 且 nums[i] + nums[j] + nums[k] == 0 的不重复三元组。
示例：[-1, 0, 1, 2, -1, -4] → [[-1,-1,2], [-1,0,1]]

一、复杂度演进：为什么 O(n²) 就够了

超时风险
O(n³)

暴力枚举：三重循环遍历所有组合 i<j<k，n=3000 时约 10⁹ 次运算，必然超时。

可行但难去重
O(n²) 哈希

固定 i + 哈希找两数：类比「两数之和」，但用哈希表存放结果会引入大量重复三元组，去重逻辑繁琐。

本题标准解
O(n²) 双指针

排序 + 双指针：外层固定一个数 O(n)，内层双指针扫描 O(n)，总复杂度 O(n²)。排序后天然有序，去重只需一句话。

💡 核心转化：三数之和 = 枚举第一个数 nums[i]，在它右边的区间里找两个数，使它们的和等于 -nums[i] —— 问题降维成了经典的「两数之和」。

二、双指针为什么有效？（关键一步）

把数组升序排序后，在区间 [L, R] 上计算 sum = nums[i] + nums[L] + nums[R]：

  • 📊 sum < 0 → 和太小，唯一有希望的办法是让 L 右移把和变大（R 左移只会更小）；
  • 📊 sum > 0 → 和太大，让 R 左移把和变小；
  • 🎯 sum == 0 → 收获一组答案！

为什么是 O(n)？每比较一次，L 和 R 之间的距离就缩短 1，而每一次移动都排除了一整行不可能的解——没有遗漏、没有重复比较。这就是把 O(n²) 的两两枚举压成 O(n) 扫描的本质。

四、去重的三个关键点（本题最容易写错的地方）

「不重复」要求结果里不能出现值相同的三元组。排序之后，相同的数必然相邻，去重就变成了简单的「跳过邻居」：

位置规则原因
第一个数 nums[i] nums[i] == nums[i-1] 时跳过 以它开头的三元组在上一轮已经找完了
第二个数 nums[L] 命中后，L 连续右移跳过相同值 避免同一固定数下产生重复组合
第三个数 nums[R] 命中后，R 连续左移跳过相同值 同上，且 L、R 要同时再各走一步

⚠️ 另一个实用剪枝：排序后如果 nums[i] > 0，直接 break —— 最小的数都大于 0，三个正数之和不可能为 0。动画里 i=5（值为 2）时就能看到这一步。

五、复杂度总结

时间 O(n²)

排序 O(n log n) + 外层枚举 O(n) × 内层双指针 O(n)。n log n 被 n² 吞没。

空间 O(log n)

只用了排序所需的栈空间（快排递归），除返回结果外没有额外开销。
